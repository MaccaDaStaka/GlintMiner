## Требования

**На каком Linux он работает?**
На 64-битном x86 Linux с glibc 2.17 или новее, то есть практически на любом дистрибутиве, который ещё используется.
Помимо glibc ему нужен только драйвер NVIDIA: ни CUDA toolkit, ни OpenSSL, ни Python не требуются.

**Какой нужен драйвер NVIDIA?**
Собственный драйвер NVIDIA (с nvidia.com или из пакетов NVIDIA вашего дистрибутива) версии 550 или новее, а для карт
RTX 50 — 580 или новее. GlintMiner загружает две библиотеки, которые идут с ним: `libcuda.so.1` для майнинга и
`libnvidia-ml.so.1` для температур, мощности и тюнинга. Открытый драйвер nouveau майнить не может.

**Какие карты?**
NVIDIA серий RTX 30, 40 и 50 (compute capability 8.0 или новее). `glint --gpu-info` показывает, что видит GlintMiner.

**Сколько памяти?**
Около 1,5 ГБ системной памяти (ОЗУ) на карту.

## Установка и первый запуск

**Какой файл скачивать?**
`glint-…-linux.tar.gz` со страницы [последнего выпуска](https://github.com/MaccaDaStaka/GlintMiner/releases/latest).
Он распаковывается в папку `glint`, где лежат программа `glint`, файлы README и эти руководства, список изменений,
файлы лицензий, юнит systemd (`glint.service`) и файлы для [MMPOS](faq-mmpos.ru.md) (`mmpos/`) и
[Docker](faq-docker.ru.md) (`docker/`).

**Как его запустить?**

```
tar xzf glint-*-linux.tar.gz
cd glint
./glint
```

При первом запуске он спросит, как вы хотите получать выплаты, и задаст ещё несколько вопросов
([Начало работы](getting-started.ru.md)). Для настройки нужен терминал. Если запустить его без терминала и без
кошелька, GlintMiner остановится с сообщением *no wallet configured: run glint in a terminal for the setup, or pass
--wallet ADDRESS* (кошелёк не задан: запустите glint в терминале для настройки или передайте --wallet АДРЕС). С
`--wallet` в командной строке он пропускает настройку и при первом запуске сохраняет ваши параметры в `glint.json`.

**Настройка не нашла мой адрес в буфере обмена.**
В Linux GlintMiner читает буфер обмена только внутри графического сеанса, с помощью `wl-paste` (Wayland) либо `xclip`
или `xsel` (X11). По SSH или без одной из этих утилит просто вставьте адрес, когда настройка его спросит.

**Где GlintMiner хранит свои файлы?**
Рядом с программой `glint`: `glint.json` (настройки и сохранённые результаты тюнинга), `glint.log`,
`glint-history.jsonl` и `glint-benchmarks.json`. `glint.json` доступен для чтения только пользователю, который его
сохранил, потому что в нём может быть токен Telegram-бота. С `--config /path/rig.json` файлы хранятся рядом с этим
файлом.

**Панель не открылась в браузере.**
GlintMiner открывает её (через `xdg-open`) только когда работает в графическом сеансе и без `--plain`. На сервере или
по SSH откройте адрес сами; см. [панель](#панель-на-десктопе-и-на-риге-без-монитора) ниже.

## Работа в фоне

**Как запустить его службой, которая стартует при загрузке?**
В загрузку входит юнит systemd, `glint.service`:

1. Поместите содержимое папки `glint` в `/opt/glint`.
2. Скопируйте `glint.service` в `/etc/systemd/system/` и впишите свой кошелёк (и имя воркера) в его строку
   `ExecStart`.
3. Выполните `systemctl enable --now glint`.

После этого GlintMiner запускается при загрузке, а systemd перезапускает его через 10 секунд после любой остановки.
Юнит запускает его от root, чтобы защита от перегрева и автотюнинг могли менять настройки карты, и с `--plain`, чтобы
его вывод нормально читался в журнале.

**Я изменил настройку на панели, но после перезапуска служба использует старую.**
Параметры командной строки при каждом запуске важнее `glint.json`. Всё, что есть в строке `ExecStart` юнита (кошелёк,
имя воркера, простая консоль), применяется каждый раз, поэтому меняйте это в юните, а затем выполните `systemctl
daemon-reload` и `systemctl restart glint`. Настройки, которых нет в командной строке, сохраняются с панели.

**Как его остановить?**
В терминале нажмите **Ctrl+C**. Если это служба — `systemctl stop glint`. GlintMiner также корректно
останавливается, получив SIGTERM или SIGHUP (закрытие терминала). В любом случае он сначала возвращает всё, что
изменил на картах.

**Что если его убьют через `kill -9` или пропадёт питание?**
Следующий запуск сначала приберётся: прежде чем какая-либо карта начнёт майнить, карты, которые менял автотюнинг,
возвращаются к прежним настройкам, а в логе появляется *auto-tune: GlintMiner didn't close cleanly last time; 1 card(s)
put back to stock* (в прошлый раз GlintMiner закрылся некорректно; карты возвращены на сток). Лимит мощности, который
снижала только защита от перегрева, в эту запись не входит, поэтому он может не вернуться к прежнему значению до
перезагрузки машины.

**Можно вместо этого запускать его в `screen` или `tmux`?**
Да; он ведёт себя так же, как в любом терминале. Отключитесь от сеанса, и он продолжит майнить.

## Права root

**Нужен ли root?**
Для майнинга — нет. Root нужен только для того, чтобы менять настройки карты:

- чтобы понемногу снижать лимит мощности карты, когда она перегревается,
- для режима прибыли (`--profit-mode`),
- для [автотюнинга](auto-tune.ru.md).

*Аварийная пауза*, которая останавливает карту вблизи точки аварийного отключения, работает и без root. Настройка
сообщает, когда тюнингу он нужен: *Tuning needs root (sudo): until then your card simply mines at stock.* (тюнингу
нужен root (sudo): до тех пор карта просто майнит на стоке).

**Как запустить его с правами root?**
`sudo ./glint` или в виде службы systemd, описанной выше (она работает от root). В Linux GlintMiner не может сам
перезапуститься с правами root, как он предлагает в Windows.

**После одного запуска через `sudo` он падает с «Permission denied» под обычным пользователем.**
Файлы, которые GlintMiner сохранил, работая от root, принадлежат root, а `glint.json` доступен для чтения только
владельцу. Запускайте его каждый раз одинаково или верните файлы своему пользователю, например
`sudo chown $USER glint.json glint.log glint-history.jsonl`.

## Автотюнинг в Linux

Полное руководство — [Автотюнинг](auto-tune.ru.md). Здесь то, что касается именно Linux.

**Как его включить?**
При настройке, на панели (**Настройки → Тюнинг**) или командой `sudo ./glint --tune speed --confirm-tuning` (либо
`efficiency`, либо `profit` вместе с `--kwh-price`). `--confirm-tuning` подтверждает, что вы принимаете риск; это
сохраняется.

**Нужны ли автотюнингу рабочий стол, X или nvidia-settings?**
Нет. GlintMiner вносит изменения через библиотеку управления драйвера NVIDIA, поэтому он работает и на машине без
монитора. Ему нужны root и драйвер, который даёт эти средства управления; со старым драйвером карта сообщает *Tuning
needs a newer NVIDIA driver: update it and start GlintMiner again. Until then this card mines at stock.* (тюнингу
нужен более новый драйвер NVIDIA; до тех пор карта майнит на стоке).

**Замечает ли GlintMiner другие программы разгона в Linux?**
Запущенные программы тюнинга он ищет только в Windows. В Linux разгон, который уже есть на карте (из nvidia-settings,
скрипта или другой программы), замечается в начале тюнинга: GlintMiner сначала возвращает карту к заводским
настройкам, пишет в лог *Your card had its own overclock; tuning starts from factory settings and puts yours back
when GlintMiner closes.* (у карты был свой разгон; тюнинг начинается с заводских настроек, а ваш разгон вернётся при
закрытии GlintMiner) и возвращает ваши настройки при закрытии. То, что меняет частоты карты *во время* тюнинга, не
замечается и портит результат, поэтому не запускайте такие скрипты или программы, пока идёт тюнинг.

**Можно на одних картах оставить свой разгон, а на других включить автотюнинг?**
Да. Карта в режиме **Выкл.** остаётся ровно такой, какая есть. Задайте это для каждой карты на панели или с помощью
`--tune-card 0=speed,1=off` (карту можно указать по номеру или по адресу шины PCI, например `01:00.0`).

**Карта упала во время тюнинга, и GlintMiner перезапустился.**
Это тюнинг нашёл предел карты. GlintMiner пишет в лог *a GPU stopped responding; restarting GlintMiner* (GPU
перестал отвечать; перезапуск GlintMiner), запускает свою новую копию и продолжает. Под systemd параметр юнита
`Restart=always` гарантирует, что он вернётся, что бы ни случилось.

## Температура и мощность

**Как GlintMiner управляет температурой?**
Он постоянно следит за температурой каждой карты. Выше предела карты он понемногу снижает лимит мощности (с root).
Вблизи точки аварийного отключения он ставит эту карту на паузу, пока она не остынет (с root или без). По умолчанию
предел считывается с вашей карты; свой можно задать в **Настройки → Температура и мощность**. Подробнее — в разделе
[Пределы температуры](auto-tune.ru.md#пределы-температуры).

**В логе написано, что лимит мощности «cannot be changed».**
*GPU 0: 84 C is over the 80 C limit, but the power limit cannot be changed. Run GlintMiner as administrator to let it
manage temperature.* (GPU 0: 84 °C выше предела 80 °C, но лимит мощности нельзя изменить; запустите GlintMiner от
имени администратора, чтобы он мог управлять температурой). В Linux это значит: запустите его от root.

**Он управляет вентиляторами?**
Нет. GlintMiner никогда не меняет скорость вентиляторов. Если карта работает с вентилятором на 100% и всё равно
горячая, в логе появится *check airflow and dust* (проверьте продув и пыль).

## Панель на десктопе и на риге без монитора

**Где панель?**
По адресу **http://127.0.0.1:4078** на машине, которая майнит. По умолчанию она отвечает только там.

**Как открыть её с другого компьютера?**
Запустите GlintMiner с `--api-bind 0.0.0.0` (или **Настройки → Панель → Кто может её открыть** → *Другие
устройства*, затем перезапуск) и откройте `http://<machine-ip>:4078`. С других устройств она доступна только для
просмотра; добавьте `--api-allow-remote-control`, чтобы разрешить изменения и с них, — только в сети, которой вы
доверяете. Если у вас работает брандмауэр, откройте TCP-порт 4078 только для своей сети. Чтобы заходить откуда
угодно, используйте Tailscale ([Доступ с телефона](phone-access.ru.md#откуда-угодно-через-tailscale)).

**Страница показывает только слово «forbidden».**
Вы открыли её по имени с точкой, например `http://rig.lan:4078`. Чтобы защитить вас от вредоносных веб-страниц,
GlintMiner отвечает только на IP-адрес, простое имя машины (`http://rig:4078`), имя в `.local` или имя Tailscale,
оканчивающееся на `.ts.net`.

**В логе написано «The dashboard and stats API couldn't start».**
Остаток строки объясняет причину, например *port 4078 is already in use (another miner, or a second GlintMiner?);
choose another with --api-port* (порт 4078 уже занят — другим майнером или вторым GlintMiner?; выберите другой с
помощью --api-port). Майнинг продолжается без панели.

## Лог

**Где лог?**
В `glint.log` рядом с программой (рядом с файлом `--config`, если вы его используете). Каждая строка начинается со
времени в виде Unix-метки, за ним идёт сообщение; `date -d @1759132800` превращает метку в дату. Когда файл вырастает
больше 8 МБ, GlintMiner при следующем запуске начинает его заново. Если это служба, её вывод показывает и
`journalctl -u glint`.

**Почему время в консоли отличается от моих часов?**
Оно указано в UTC, а не в вашем местном времени.

**Что есть в `glint.log` такого, чего нет на экране?**
Технические подробности. Консоль и панель показывают короткое предложение о том, что случилось и что делать;
веб-адреса, системные коды ошибок и подробности ошибок попадают в `glint.log`. Если выключить файл лога
(`--no-log-file`), подробности выводятся в консоль, в квадратных скобках после предложения.

**Как поделиться логом, когда прошу помощи?**
Скопируйте строки вокруг проблемы (например, `tail -n 200 glint.log`) и приложите их вместе с выводом
`./glint --self-test` к вашему [issue](faq.ru.md#как-получить-помощь). Если не хотите делиться адресом кошелька,
сначала удалите его.

## Обновление и удаление

**Как я узнаю о новой версии?**
GlintMiner проверяет GitHub при запуске и раз в день и пишет в логе и на панели *A newer GlintMiner (…) is available
at https://github.com/MaccaDaStaka/GlintMiner/releases* (доступна более новая версия GlintMiner). Сам он никогда
ничего не скачивает и не устанавливает.

**Как обновиться?**
Остановите GlintMiner, замените программу `glint` той, что из нового `glint-…-linux.tar.gz`, и запустите снова (если
это служба: `systemctl restart glint`). Сохраните `glint.json` и остальные файлы: ваши настройки, сохранённые
результаты тюнинга и история останутся.

**Как его удалить?**
Остановите его и удалите его папку. Если вы настроили его как службу, сначала выполните `systemctl disable --now
glint` и удалите `/etc/systemd/system/glint.service`. Больше GlintMiner ничего не устанавливает.

## Несколько карт

**Он использует все мои карты?**
Да, все поддерживаемые карты NVIDIA, и модели можно смешивать. Выбрать можно с помощью `--devices 0,2` или
**Настройки → Майнинг → Какие карты использовать**. Подробнее — в разделе
[Несколько видеокарт и несколько ригов](advanced.ru.md#несколько-видеокарт-и-несколько-ригов).

**Почему «GPU 1» у GlintMiner — это другая карта, чем GPU 1 у nvidia-smi?**
GlintMiner нумерует карты в порядке CUDA, который на машине с разными картами может отличаться от порядка nvidia-smi.
`glint --gpu-info` показывает номер каждой карты вместе с её названием и адресом шины PCI, так что их можно
сопоставить.

## Сообщения и что они значат

| Что вы видите | Что это значит | Что делать |
|---|---|---|
| *No NVIDIA driver was found. Install the current GeForce driver from nvidia.com and start again.* | Не удалось загрузить `libcuda.so.1` | Установите драйвер NVIDIA (не nouveau) |
| *No NVIDIA GPU was found. GlintMiner needs an RTX 30-series or newer card.* | Драйвер не видит карту, которую может использовать GlintMiner | Проверьте `nvidia-smi` и `glint --gpu-info` |
| *Your NVIDIA driver is too old for this GPU. Update to driver 550 or newer (580+ for RTX 50) and start again.* | Драйвер старше вашей карты или GlintMiner | Обновите драйвер |
| *…is not supported: Pearl mining needs an RTX 30-series or newer* | Эта карта слишком старая | Эта карта пропускается; остальные майнят |
| *The GPU ran out of memory. Close other GPU programs (games, other miners) and start again.* | Память карты занята чем-то ещё | Закройте это и запустите снова |
| *no wallet configured: run glint in a terminal for the setup, or pass --wallet ADDRESS* | Запуск без терминала и без настроек | Запустите его один раз в терминале или добавьте `--wallet` |
| *reading …/glint.json: Permission denied* | Файл принадлежит root (см. выше) | Запускайте каждый раз одинаково или смените владельца файла через `chown` |
| *Can't look up … — check this PC's internet or DNS settings.* | Не удаётся найти адрес пула по имени | Проверьте сеть и DNS |
| *Couldn't set up a secure connection to …; check this PC's date and time, and any antivirus or firewall that inspects traffic.* | Не удалось установить зашифрованное соединение | Исправьте часы (NTP); проверьте всё, что перехватывает трафик |
| *The pool is not accepting our work (…). Pearl's rules may have changed (a network upgrade): this version needs an update.* | GlintMiner остановился, чтобы не отправлять работу, которую отклонят | [Обновитесь](#обновление-и-удаление) |
| *Tuning needs administrator rights: close GlintMiner and start it again with right-click, Run as administrator (on Linux, with sudo).* | Тюнинг включён без root | Запустите его от root |

GlintMiner подключается к вашему пулу (HeroMiners на порт 1200, Kryptex на 8048, unMineable на 4444 или 3333) и к
сайтам на порт 443 за ценами, данными вашего пула и проверкой обновлений. Если вы фильтруете исходящий трафик,
разрешите эти подключения. Больше ответов — в разделе [Что значат сообщения](auto-tune.ru.md#что-значат-сообщения) и
в [таблице решения проблем](faq.ru.md#решение-проблем).
