## Командная строка

```
glint --wallet prl1... --worker rig1
glint --wallet prl1... --pool stratum+ssl://prl.kryptex.network:8048
glint --wallet krx... --worker rig1
glint --wallet BTC:bc1q... --kwh-price 0.12 --currency EUR
glint --wallet prl1... --devices 0,1 --api-bind 0.0.0.0 --plain
glint --wallet prl1... --tune speed --confirm-tuning --save
```

Параметры из командной строки действуют на этот запуск. Добавьте `--save`, чтобы записать их в `glint.json`, — тогда
простой запуск `glint` (или двойной щелчок) будет использовать их и дальше.

**Маршрут определяется кошельком:**

| `--wallet` | Где майнит | Выплаты в |
|---|---|---|
| `prl1…` (адрес Pearl) | HeroMiners, ближайший сервер (0% комиссия пула) | PRL |
| `prl1…` с `--pool stratum+ssl://prl.kryptex.network:8048` | Kryptex (2%, оплата за каждый шар) | PRL |
| `krx…` или email аккаунта Kryptex | Kryptex | BTC, вывод в BTC, USDT или USDC |
| `COIN:address`, например `BTC:bc1q…`, `DOGE:D…`, `SOL:…` | unMineable (1%) | Эта монета |

## Все параметры

| Параметр | Назначение |
|---|---|
| `--wallet ADDRESS` | Куда получать доход (см. таблицу выше) |
| `--coin TICKER` | Монета для адреса, который подходит нескольким (например, адрес `0x…`: ETH, USDT, …) |
| `--worker NAME` | Имя этого рига на пуле (буквы, цифры, `-` и `_`) |
| `--pool URL` | Этот пул вместо автоматического выбора (`stratum+ssl://host:port`) |
| `--devices 0,1` | Майнить только на этих GPU (номера как в `glint --gpu-info`); по умолчанию — на всех |
| `--kwh-price 0.12`, `--currency EUR` | Ваша цена электричества и валюта — для расчёта прибыли за вычетом электричества |
| `--profit-mode` | Раз в день подбирать самый выгодный лимит мощности (нужны `--kwh-price` и права администратора) |
| `--tune MODE` | Автотюнинг: `profit` (лучший заработок), `speed` (максимальный хешрейт), `efficiency` (меньше мощности), `cool` (прохладно и тихо, со степенью `--cool-strength`; или `cool:cool`, `cool:cooler`, `cool:coolest`) или `off` (права администратора; в первый раз — `--confirm-tuning`) |
| `--cool-strength cooler` | Насколько далеко идёт «Прохладно и тихо»: `cool` (примерно на четверть меньше мощности, чем на стоке), `cooler` (примерно на треть, по умолчанию) или `coolest` (примерно на 45%); никогда не ниже 70% стоковой скорости. Сохраняется как `cool_strength`. У каждой степени свой тюнинг. См. [«Прохладно и тихо»](auto-tune.ru.md#варианты) |
| `--confirm-tuning` | Подтверждает, что вы принимаете риск автотюнинга (сохраняется) |
| `--tune-card 0=speed,1=cool:coolest,2=off` | Свой режим для каждой карты (`default` — как у `--tune`; просто `cool` — степень рига); карты не из списка следуют `--tune` |
| `--tune-exclude 0,2` | Оставить эти карты на стоке, пока остальные настраиваются |
| `--retune [РЕЖИМ]` | Забыть сохранённые результаты тюнинга и заново настроить все карты со стока, во всех режимах. С режимом (`--retune cool:cooler`, `--retune efficiency`; просто `cool` означает силу из `--cool-strength`) забываются только результаты для этого режима; результаты карт для других режимов сохраняются. Вместе с `--tune-card` заново настраиваются только перечисленные там карты, каждая в указанном для неё режиме (`--tune-card 07:00.0=efficiency --retune`); их результаты для других режимов и тюнинг остальных карт сохраняются. Уберите его, когда тюнинг начался: если он остаётся (полётный лист HiveOS), тюнинг начинается заново при каждом запуске |
| `--tune-reset` | Забыть сохранённые результаты тюнинга, режимы карт и исключения и выключить тюнинг |
| `--tune-at-once N` | Настраивать до N карт одновременно (по умолчанию 1). **Каждая карта во время тюнинга работает на заводских настройках — горячее и громче вашего разгона — 1–2 часа**: N сразу — это N карт на стоке одновременно. Пусть вентиляторы следуют за температурой (AutoFan в HiveOS или mmpOS с целевой температурой или кривая вентиляторов) или поставьте фиксированные обороты 70% и выше, и убедитесь, что охлаждение и блок питания это выдержат; сбой сложнее связать с картой, которая его вызвала. Ожидающие карты сохраняют свои настройки или работают на пониженной мощности. Если карты продолжают переставать отвечать, пока несколько настраиваются вместе, остаток тюнинга идёт по одной карте, а если и так не помогает — тюнинг встаёт на паузу ([как](auto-tune.ru.md#риги-с-несколькими-картами)) |
| `--tune-power-budget ВАТТЫ` | Пока карты настраиваются, держать весь риг ниже этого числа ватт (0 или `off` — без бюджета, по умолчанию). Сначала снижается мощность ожидающих карт; карта начинает тюнинг, только когда укладывается в бюджет. Есть и в Настройках |
| `--speed-power-raise max` | Сколько мощности режим «Максимальный хешрейт» может добавить каждой карте, от безопасного к рискованному: `none` (никогда выше стока), `low` (до 10% больше), `medium` (до 25% больше) или `max` (до максимума самой карты, по умолчанию); либо наибольшее число ватт, которое можно добавить на карту, например `50`. Есть и в Настройках. См. [Риги с несколькими картами](auto-tune.ru.md#риги-с-несколькими-картами) |
| `--speed-power-raise-card 0=none,1=50` | То же для одной карты (по номеру или PCI-шине) вместо `--speed-power-raise`; `rig` снова следует значению рига. Сохраняется как `speed_power_raise_cards` |
| `--temp-limit auto` | Температура, ниже которой GlintMiner держит каждую карту, снижая её мощность (права администратора): `auto` (по умолчанию, от безопасного максимума самой карты), число от 60 до 95 (°C; никогда выше максимума самой карты) или `off`. Есть и в Настройках |
| `--temp-limit-card 0=75,2=70` | Свой предел температуры для каждой карты (по номеру или PCI-шине) вместо `--temp-limit`, от 60 до 95 °C и никогда выше максимума самой карты; `auto` снова следует пределу рига. Для карты в жарком месте, например между двумя другими. Автотюнинг тоже его соблюдает. Сохраняется как `temp_limits` |
| `--tune-ignore-tools` | Настраивать, даже когда запущен MSI Afterburner или похожая программа (она может менять частоты посреди тюнинга) |
| `--schedule 23:00-07:00=cool:coolest,17:00-21:00=pause` | Часы для другого режима (`off`, `speed`, `efficiency`, `cool:cool`, `cool:cooler`, `cool:coolest`; просто `cool` — степень рига) или паузы (`pause`); `--schedule off` выключает. См. [расписание](auto-tune.ru.md#расписание) |
| `--game-pause`, `--no-game-pause` | Windows: пауза майнинга, пока игра нагружает видеокарту (включена по умолчанию) |
| `--share-diff N` | Только Kryptex: сложность шара, которую запросить у пула (0 = автоматически) |
| `--auto-update ask` | Обновления: `ask` (по умолчанию: вы выбираете «Обновить сейчас», «Позже» или «Пропустить»), `auto` (установка, когда ни одна карта не в середине тюнинга, затем перезапуск) или `off` (без проверок). См. [Обновления](../README.ru.md#обновления) |
| `--affiliate КОД` | Партнёрский код того, кто вас пригласил (`off` убирает его; хранится в `glint.json` как `"affiliate"`). Вы по-прежнему платите 1%: четверть уходит партнёру. См. [FAQ](faq.ru.md#вопросы) |
| `--github-proxy URL` | Для сетей, где GitHub недоступен (материковый Китай): прокси, через который запрашиваются ссылки GitHub, например `https://v4.gh-proxy.org/` (`off` убирает его; хранится в `glint.json` как `"github_proxy"` или задаётся в Настройки → Майнинг). Используется для списка партнёрских кодов и обновлений, подписи которых по-прежнему проверяются. См. [FAQ](faq.ru.md#вопросы) |
| `--api-port 4078` | Порт панели |
| `--api-bind 0.0.0.0` | Открыть панель для вашей сети (с других устройств — только просмотр) |
| `--api-allow-remote-control` | Разрешить с этих устройств и изменения, с кодом удалённого управления (печатается при запуске и показан в панели на этом ПК; только в сети, которой вы доверяете) |
| `--open-dashboard`, `--no-open-dashboard` | Открывать или не открывать панель в браузере при запуске |
| `--telegram-token TOKEN`, `--telegram-chat ID` | Уведомления в Telegram, если карта остановилась или пропала связь с пулом |
| `--plain` | Простые строки лога вместо живой таблицы (службы, ОС для ригов, экранные дикторы) |
| `--no-log-file` | Не писать `glint.log` |
| `--no-log-share` | Не отправлять с отметкой обезличенные выдержки из журнала GlintMiner (включено по умолчанию; хранится в `glint.json` как `"log_share"`, также в Настройки → Консоль). `--no-telemetry` отключает и отметку, и журналы. См. [Диагностические журналы](../README.ru.md#диагностические-журналы-с-129) |
| `--save` | Записать эти параметры в `glint.json` |
| `--config PATH` | Другой файл настроек (по умолчанию `glint.json` рядом с `glint`) |

Полный список всегда есть в `glint --help`. Подробно об автотюнинге: [Автотюнинг](auto-tune.ru.md).

## Диагностика

| Команда | Что делает |
|---|---|
| `glint --self-test` | Проверяет карту, драйвер и код майнинга от начала до конца, затем завершается. Прикладывайте её вывод к сообщениям об ошибках |
| `glint --gpu-info` | Показывает ваши карты NVIDIA с их номерами, памятью, драйвером и compute capability |
| `glint --bench 60` | Майнит офлайн 60 секунд и сообщает хешрейт (результат сохраняется). Карта RTX 50 сначала сравнивает свои способы майнинга, как при каждом запуске (несколько минут), и замер идёт тем, который она оставляет; строка результата говорит каким |
| `glint --benchmarks` | Показывает сохранённые результаты замеров |
| `glint --pools ADDRESS` | Показывает, какой пул и маршрут будет использовать адрес |
| `glint --net-test host:port` | Проверяет соединение с сервером пула |
| `glint --update [ВЕРСИЯ]` | Проверяет, есть ли новая версия, сверяет подпись, устанавливает и запускает её (если GlintMiner уже работает на этом ПК, обновляется он сам); `ВЕРСИЯ` выбирает выпуск, в том числе более старый; `--no-start` — только установить |
| `glint --become-affiliate` | Заявка на партнёрство на риге без экрана: показывает ровно то, что будет отправлено, и отправляет только после того, как вы наберёте `yes`; запустите снова, чтобы увидеть статус (ждёт, одобрена с вашим кодом, отклонена или отозвана). Работающий майнер, пока заявка ждёт, и сам проверяет её примерно раз в час и после одобрения пишет ваш код в журнал и на панель |

## Несколько видеокарт и несколько ригов

- **Один ПК, несколько карт.** GlintMiner автоматически использует все поддерживаемые карты NVIDIA в ПК, модели можно
  смешивать (например, 3080 и 4070). У каждой карты своя строка в консоли и на панели: свой хешрейт, температура,
  мощность и шары. Карты делят одно подключение к пулу, поэтому пул видит одного воркера на ПК.
- **Выбор карт для майнинга:** `--devices 0,2` или Настройки → Майнинг → Какие карты использовать.
- **Сбой одной карты не останавливает остальные.** Если карта не запустилась, остальные продолжают майнить, а консоль
  сообщает причину. Если карта перестала отвечать, GlintMiner перезапускается и продолжает работу.
- **О каждой карте заботятся отдельно:** температурная защита и автотюнинг работают с каждой картой по отдельности.
  См. [Риги с несколькими картами](auto-tune.ru.md#риги-с-несколькими-картами). Карта, которая греется сильнее
  остальных (в середине стопки, рядом с блоком питания), может получить свой, более низкий предел:
  `--temp-limit-card 1=72`.
- **Горячая память:** у RTX 3080, 3090, 3090 Ti и 4070 Ti и выше память может дойти до своего предела, пока
  температура карты выглядит нормально (драйвер не сообщает температуру памяти на этих картах). Когда карта
  замедляется от нагрева именно так, GlintMiner снижает её мощность, пока замедление не прекратится, и пишет об этом
  в журнале. Больше всего помогает хороший обдув задней стороны карты.
- **Блок питания:** карты, ждущие очереди на тюнинг, работают на пониженной мощности, а `--tune-power-budget` держит
  весь риг ниже заданного числа ватт, пока идёт тюнинг. «Максимальный хешрейт» может дать карте больше мощности, чем
  на стоке, если это даёт прирост (по умолчанию до максимума самой карты), и риг потребляет всё это сразу, только когда
  каждая карта работает со своим результатом: если риг близок к пределу блока питания, выберите меньше с помощью
  `--speed-power-raise none|low|medium` (Настройки → Температура и мощность → Доп. мощность для «Максимальный
  хешрейт»), задайте бюджет или настройте на «Меньше мощности».
- **Несколько ПК:** запускайте GlintMiner на каждом со своим именем воркера (`--worker rig2`), все на один кошелёк.
  Пул показывает каждый ПК отдельно, а страница «Доход» на панели — все риги на этом кошельке.
- **Память:** рассчитывайте примерно на 1,5 ГБ оперативной памяти (RAM) на каждую GPU.

## Пулы и выплаты

- **Автоматический выбор пула.** Для адреса Pearl GlintMiner выбирает ближайший сервер HeroMiners и переключается на
  другой, если тот становится недоступен. Соединения шифруются (TLS).
- **Свой пул:** `--pool stratum+ssl://host:port` или Настройки → Майнинг → Свой пул.
- **Шары меньше на HeroMiners и Kryptex.** Шар Pearl весит около 2 МБ. На HeroMiners GlintMiner отправляет их сжатыми
  (около 14 КБ каждый); если какой-то сервер HeroMiners их не примет, до конца работы этому серверу отправляются
  несжатые шары. На Kryptex шары сжимаются (около 11 КБ), если Kryptex соглашается на это при входе. Меньше трафика и
  меньше устаревших шаров на медленном соединении.
- **Сложность шара на Kryptex.** Большой риг (больше 500 TH/s) автоматически просит у Kryptex более высокую сложность
  шара — примерно один шар в 30 секунд, чтобы не засыпать пул шарами. Свою можно задать через `--share-diff N`.
  По умолчанию у Kryptex 2097152; формула: *хешрейт в H/s × секунд на шар ÷ 4294967296*. Заработок от этого не
  меняется: каждый шар просто стоит больше.

## HiveOS, MMPOS, Docker и службы Linux

- **HiveOS:** добавьте кастомный майнер по ссылке на `glint-….tar.gz` из Releases. Пошагово, включая статистику
  и открытие панели с другого компьютера: [HiveOS](../hiveos/README.md).
- **MMPOS:** [MMPOS](../mmpos/README.md).
- **Docker:** [Docker](../docker/README.md). На хосте нужен NVIDIA Container Toolkit.
- **Служба Linux (systemd):** скопируйте [`glint.service`](../glint.service) в `/etc/systemd/system/`, впишите в него
  свой кошелёк и выполните `systemctl enable --now glint`. Тогда GlintMiner запускается при загрузке и перезапускается,
  если вдруг остановится. Для служб используйте `--plain`, чтобы лог нормально читался в `journalctl -u glint`.
- **Автотюнингу в Linux** нужен root, потому что без него частоты не изменить.

## API статистики

GlintMiner отдаёт JSON на порту панели — для вашего собственного мониторинга и для ОС для ригов:

- `GET http://127.0.0.1:4078/api/stats`: общий хешрейт и хешрейт по картам (H/s), температуры, вентиляторы, мощность,
  шары (принятые, отклонённые, устаревшие), время работы, версия, оценка дохода и данные пула по кошельку.
  `status.state` равно `held`, пока майнинг на паузе из-за игры или по расписанию, а `hold` говорит, почему
  (`{"kind": "game", "program": "…"}` или `{"kind": "schedule", "until": "07:00"}`).
  `work.late` равно true, пока карты добывают по заданию, которое пул уже заменил, потому что процессор слишком занят,
  чтобы вовремя готовить новую работу; `work.job_lag_s` — сколько секунд назад пул прислал новое задание,
  `work.trees_s` — время подготовки последнего задания; у каждой карты есть свой `job_lag_s`.

API отвечает только на `127.0.0.1`, если не запустить GlintMiner с `--api-bind 0.0.0.0`. Хешрейт — в H/s, где 1 H —
это одно умножение-накопление Pearl.

| Файл | Что в нём |
|---|---|
| `glint.json` | Ваши настройки, сохранённые результаты тюнинга (по одному на карту и режим), расписание и программы, которые не ставят майнинг на паузу. Сохраняйте его при обновлении; удалите, чтобы пройти настройку заново |
| `glint.log` | Лог: что и когда произошло, с техническими подробностями любых ошибок. Прикладывайте нужные строки к сообщениям об ошибках |
| `glint-history.jsonl` | Поминутная запись хешрейта, мощности и дохода — для графиков и итогов на панели |
| `glint-benchmarks.json` | Результаты `--bench` |
| `glint-update.json` | Ваш выбор об обновлениях (пропущенные версии, «Позже») и первые минуты новой версии, для отката |
| `glint.prev.exe` / `glint.prev` | Предыдущая программа, сохранённая обновлением (возвращается, если новая работает неправильно) |

Паролей ни в одном из них нет. В `glint.json` хранятся ваш адрес для выплат и, если вы их указали, токен Telegram-бота
и chat id.
